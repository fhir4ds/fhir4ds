# Benchmark Baselines

This directory contains checked-in performance baselines used by report-only
benchmark comparison tooling.

## DQM 2025 Baseline

`dqm_2025.json` is the baseline for the QI-Core 2025 DQM conformance timing
suite. It has the same structure as `conformance/reports/dqm_report.json`,
generated by:

```bash
python3 conformance/scripts/run_dqm.py
```

The DQM performance workflow compares the current report to this baseline with:

```bash
python3 benchmarks/runner/dqm_perf_report.py \
  --current conformance/reports/dqm_report.json \
  --baseline benchmarks/baselines/dqm_2025.json \
  --output-json benchmarks/output/dqm-performance-report.json \
  --output-md benchmarks/output/dqm-performance-report.md
```

## When to Update

Update the baseline when a performance change is intentional and reviewed, for
example:

- A translator optimization improves one or more measures.
- A correctness change necessarily increases SQL generation or execution time.
- The benchmark fixture suite changes.
- The CI runner environment changes enough that old timings are no longer
  comparable.

Do not update the baseline just to hide an unexplained regression.

## Update Procedure

1. Run the DQM conformance suite locally:

   ```bash
   python3 conformance/scripts/run_dqm.py
   ```

2. Confirm the run is still fully conformant:

   ```text
   Summary: 47/47 measures passed (100.0%)
   ```

3. Review the generated timings in `conformance/reports/dqm_report.json`.

4. Copy the report into the baseline:

   ```bash
   cp conformance/reports/dqm_report.json benchmarks/baselines/dqm_2025.json
   ```

5. Generate and review the comparison report:

   ```bash
   python3 benchmarks/runner/dqm_perf_report.py \
     --current conformance/reports/dqm_report.json \
     --baseline benchmarks/baselines/dqm_2025.json \
     --output-json benchmarks/output/dqm-performance-report.json \
     --output-md benchmarks/output/dqm-performance-report.md
   ```

6. Commit the baseline with a message that explains why the performance
   expectation changed.

## Thresholds

The report flags a measure only when both thresholds are exceeded:

- Current metric is at least `2.0x` the baseline.
- Current metric increased by at least `500 ms`.

The default workflow is non-blocking. Use `--fail-on-regression` only after the
baseline and hosted runner variability are stable enough for a hard gate.
