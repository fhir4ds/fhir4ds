# FHIR REST API

Every example on this page runs **live** against the public demo server,
**[bulk-publish-demo-server](https://fhir4ds-bulk-publish-demo-server.hf.space)** —
a FHIR4DS instance seeded with the SMART Scheduling Links example dataset
(11.5k `Slot`, 25 `Schedule`, plus `Location`, `PractitionerRole`, `Device`).
Press **Run** and the real request executes from your browser; no setup, no key
needed for reads.

The API has two tiers:

| Tier | What | Authentication |
| --- | --- | --- |
| **Open** | Reads, search, `_history`, running *stored* ViewDefinitions and SQL queries | None |
| **Write** | `POST`/`PUT`/`DELETE` resources, `POST /Bundle`, flush | `X-Write-Key` header |

The dataset behind the server stays private; this API is the window onto it.
Every write is versioned and published to an append-only parquet dataset, so
results survive server restarts.

## Discover the server

Every FHIR conversation starts at the CapabilityStatement.

<TryIt method="GET" path="/metadata" label="CapabilityStatement" />

```javascript
const capability = await (await fetch(`${BASE}/metadata`)).json();

```

</TabItem>
<TabItem value="python" label="Python">

</TabItem>

## Post a resource

Create a `Slot` (any FHIR resource type works — `Schedule`, `Patient`, …).
The server assigns a version id and returns it as an `ETag`.

The runner below uses `PUT` (create-or-update), so you can press Run as many
times as you like — enter a write key and the resource lands on the demo
server for real, then appears in every later example on this page. With an
empty key you will see the `401` refusal.

<TryIt
  method="PUT"
  path="/Slot/docs-walkin-001"
  label="upsert a Slot"
  needsKey={true}
  body={JSON.stringify({
    resourceType: 'Slot',
    id: 'docs-walkin-001',
    status: 'free',
    start: '2027-03-05T09:00:00Z',
    end: '2027-03-05T09:30:00Z',
    schedule: { reference: 'Schedule/10' },
  })}
/>

<Tabs>
<TabItem value="javascript" label="JavaScript" default>

```javascript
const created = await fetch(`${BASE}/Slot`, {
  method: "POST",
  headers: { "Content-Type": "application/fhir+json", "X-Write-Key": WRITE_KEY },
  body: JSON.stringify({
    resourceType: "Slot",
    id: "walkin-001",
    status: "free",
    start: "2027-03-05T09:00:00Z",
    end: "2027-03-05T09:30:00Z",
    schedule: { reference: "Schedule/10" },
  }),
});
console.log(created.status, created.headers.get("ETag")); // 201 W/"11630"
```

</TabItem>
<TabItem value="python" label="Python">

```python
slot = {
    "resourceType": "Slot",
    "id": "walkin-001",
    "status": "free",
    "start": "2027-03-05T09:00:00Z",
    "end": "2027-03-05T09:30:00Z",
    "schedule": {"reference": "Schedule/10"},
}
created = requests.post(
    f"{BASE}/Slot", json=slot, headers={"X-Write-Key": WRITE_KEY},
)
print(created.status_code, created.headers["ETag"])  # 201 W/"11630"
```

</TabItem>
<TabItem value="curl" label="curl">

```bash
curl -X POST "$BASE/Slot" \
  -H "X-Write-Key: $WRITE_KEY" \
  -H "Content-Type: application/fhir+json" \
  -d '{
    "resourceType": "Slot",
    "id": "walkin-001",
    "status": "free",
    "start": "2027-03-05T09:00:00Z",
    "end": "2027-03-05T09:30:00Z",
    "schedule": {"reference": "Schedule/10"}
  }'
# HTTP/1.1 201 Created
# ETag: W/"11630"
# Location: Slot/walkin-001
```

</TabItem>
</Tabs>

:::note No key, no writes
Posting without a valid `X-Write-Key` returns `401` with a FHIR
`OperationOutcome` — try the runner above with an empty key field. Re-posting
an existing id is a `400`; use `PUT /Slot/{id}` to update it.
:::

## Read, search, and history

Anyone can read what has been written. Search supports `_id`, `identifier`,
and paging (`_count`, `_offset`); richer filtering is what the
ViewDefinitions below are for.

<TryIt method="GET" path="/Slot/docs-walkin-001" label="read the slot you wrote" />

<TryIt method="GET" path="/Slot?_count=5" label="search" />

<TryIt method="GET" path="/Slot/1001/_history" label="history (seeded slot)" />

<Tabs>
<TabItem value="javascript" label="JavaScript" default>

```javascript
const slot = await (await fetch(`${BASE}/Slot/docs-walkin-001`)).json();

const search = await (await fetch(`${BASE}/Slot?_count=5`)).json();
console.log(search.total);

const history = await (
  await fetch(`${BASE}/Slot/docs-walkin-001/_history`)
).json();
```

</TabItem>
<TabItem value="python" label="Python">

```python
read = requests.get(f"{BASE}/Slot/docs-walkin-001").json()
search = requests.get(f"{BASE}/Slot", params={"_count": 5}).json()
print(search["total"])
history = requests.get(f"{BASE}/Slot/docs-walkin-001/_history").json()
```

</TabItem>
<TabItem value="curl" label="curl">

```bash
curl "$BASE/Slot/docs-walkin-001"            # read one (no key needed)
curl "$BASE/Slot?_count=5"                   # search with paging
curl "$BASE/Slot?_id=1001"                   # search by id
curl "$BASE/Slot/docs-walkin-001/_history"   # versions, newest first
```

</TabItem>
</Tabs>

## Update and delete (optimistic locking)

Updates are versioned. Send `If-Match` with the `ETag` you received; a stale
version is rejected with `412`. Deletes tombstone the resource (`410` on read)
but `_history` keeps every version.

<Tabs>
<TabItem value="javascript" label="JavaScript" default>

```javascript
const updated = await fetch(`${BASE}/Slot/walkin-001`, {
  method: "PUT",
  headers: {
    "Content-Type": "application/fhir+json",
    "X-Write-Key": WRITE_KEY,
    "If-Match": created.headers.get("ETag"),
  },
  body: JSON.stringify({ ...slot, status: "busy" }),
});
console.log(updated.status, updated.headers.get("ETag"));

await fetch(`${BASE}/Slot/walkin-001`, {
  method: "DELETE",
  headers: { "X-Write-Key": WRITE_KEY },
});
```

</TabItem>
<TabItem value="python" label="Python">

```python
updated = requests.put(
    f"{BASE}/Slot/walkin-001",
    json={**slot, "status": "busy"},
    headers={"X-Write-Key": WRITE_KEY, "If-Match": created.headers["ETag"]},
)
requests.delete(f"{BASE}/Slot/walkin-001", headers={"X-Write-Key": WRITE_KEY})
print(requests.get(f"{BASE}/Slot/walkin-001").status_code)  # 410
```

</TabItem>
<TabItem value="curl" label="curl">

```bash
curl -X PUT "$BASE/Slot/walkin-001" \
  -H "X-Write-Key: $WRITE_KEY" -H "Content-Type: application/fhir+json" \
  -H 'If-Match: W/"11630"' \
  -d '{ ...same slot, status now "busy"... }'
# HTTP/1.1 200 OK   ETag: W/"11631"

curl -X DELETE -H "X-Write-Key: $WRITE_KEY" "$BASE/Slot/walkin-001"
```

</TabItem>
</Tabs>

## Execute a stored ViewDefinition

The server ships two stored views — `slot-view` (one row per `Slot`) and
`schedule-view` (one row per `Schedule`). Running them is an open `POST`; the
query string carries operation parameters (`_format`, `_limit`, `header`).
This is also where real filtering lives — e.g. `status = 'free'`:

<TryIt method="POST" path="/ViewDefinition/slot-view/$run?_format=json&_limit=3" label="run slot-view" />

<Tabs>
<TabItem value="javascript" label="JavaScript" default>

```javascript
const rows = await (
  await fetch(`${BASE}/ViewDefinition/slot-view/$run?_limit=3`)
).json();
rows.forEach((row) => console.log(row.slot_id, row.status, row.starts_at));
```

</TabItem>
<TabItem value="python" label="Python">

```python
rows = requests.post(f"{BASE}/ViewDefinition/slot-view/$run?_limit=3").json()
for row in rows:
    print(row["slot_id"], row["status"], row["starts_at"])
```

</TabItem>
<TabItem value="curl" label="curl">

```bash
curl -X POST "$BASE/ViewDefinition/slot-view/\$run?_limit=3"              # ndjson
curl -X POST "$BASE/ViewDefinition/slot-view/\$run?_format=csv&_limit=3"  # csv
```

</TabItem>
</Tabs>

## Execute a SQL-on-FHIR query with parameters

The stored `free-slots-query` joins both views and takes a `status` parameter.
Runtime parameter values arrive as a **nested** `Parameters` resource:

  method="POST"
  path="/Library/free-slots-query/$sqlquery-run?_format=json&_limit=3"
  label="free-slots-query, status=free"
  body={JSON.stringify({
    resourceType: 'Parameters',
    parameter: [
      {
        name: 'parameters',
        resource: {
          resourceType: 'Parameters',
          parameter: [{ name: 'status', valueString: 'free' }],
        },
      },
    ],
  })}
/>

<Tabs>
<TabItem value="javascript" label="JavaScript" default>

## Post a transaction Bundle

Multiple writes ride one `POST /Bundle` with per-entry statuses:

<Tabs>
<TabItem value="javascript" label="JavaScript" default>

```javascript
const bundle = {
  resourceType: "Bundle",
  type: "transaction",
  entry: [1, 2].map((n) => ({
    request: { method: "POST", url: "Slot" },
    resource: {
      resourceType: "Slot",
      id: `bundle-slot-${n}`,
      status: "free",
      start: `2027-03-06T1${n}:00:00Z`,
      end: `2027-03-06T1${n}:30:00Z`,
      schedule: { reference: "Schedule/10" },
    },
  })),
};
const response = await fetch(`${BASE}/Bundle`, {
  method: "POST",
  headers: { "Content-Type": "application/fhir+json", "X-Write-Key": WRITE_KEY },
  body: JSON.stringify(bundle),
});
(await response.json()).entry.forEach((e) =>
  console.log(e.response.status, e.response.location),
);
```

</TabItem>
<TabItem value="python" label="Python">

```python
bundle = {
    "resourceType": "Bundle",
    "type": "transaction",
    "entry": [
        {
            "request": {"method": "POST", "url": "Slot"},
            "resource": {
                "resourceType": "Slot", "id": "bundle-slot-1",
                "status": "free",
                "start": "2027-03-06T10:00:00Z",
                "end": "2027-03-06T10:30:00Z",
                "schedule": {"reference": "Schedule/10"},
            },
        },
        {
            "request": {"method": "POST", "url": "Slot"},
            "resource": {
                "resourceType": "Slot", "id": "bundle-slot-2",
                "status": "free",
                "start": "2027-03-06T11:00:00Z",
                "end": "2027-03-06T11:30:00Z",
                "schedule": {"reference": "Schedule/10"},
            },
        },
    ],
}
response = requests.post(
    f"{BASE}/Bundle", json=bundle, headers={"X-Write-Key": WRITE_KEY}
)
for entry in response.json()["entry"]:
    print(entry["response"]["status"], entry["response"].get("location"))
```

</TabItem>
<TabItem value="curl" label="curl">

```bash
    {"request":{"method":"POST","url":"Slot"},
     "resource":{"resourceType":"Slot","id":"bundle-slot-1","status":"free",
       "start":"2027-03-06T10:00:00Z","end":"2027-03-06T10:30:00Z",
       "schedule":{"reference":"Schedule/10"}}},
    {"request":{"method":"POST","url":"Slot"},
     "resource":{"resourceType":"Slot","id":"bundle-slot-2","status":"free",
```

## The bulk-publish feed

`GET /$bulk-publish` serves the Bulk-Data-shaped manifest of the append-only
dataset every write lands in:

<TryIt method="GET" path="/$bulk-publish" label="manifest" />

On this public demo the manifest's part URLs point into the private dataset,
so they answer `401` anonymously — the API is the public window; direct
dataset consumption is for key holders. The [Bulk Publish demo](./bulk-publish.mdx)
shows the full client-side consume story against your own server.

## Error behavior worth knowing

| Situation | Response |
| --- | --- |
| Write or admin call without a valid key | `401` `OperationOutcome` |
| Unknown or mistyped operation parameter | `400` naming the parameter |
| Unsupported search parameter (only `_id`, `identifier`, paging) | `400` listing the supported set |
| `POST` an id that already exists | `400` (use `PUT` to update) |
| Same parameter in body **and** query string | `400` (ambiguous) |
| Update with a stale `If-Match` version | `412` |
| Read of a deleted (or never-created) resource | `404` / `410 Gone` (`_history` keeps versions) |
| Request body over the server cap | `413` |
| Query exceeding the server time limit | `408` |

Interactive OpenAPI docs live at
[`$BASE/docs`](https://fhir4ds-bulk-publish-demo-server.hf.space/docs).

## Run your own

The demo server is one `pip install` away:

```bash
pip install "fhir4ds-v2[serve,hf]"
fhir4ds serve --port 8766 --resources ./fhir-data \
  --admin-key "$ADMIN_KEY" --write-key "$WRITE_KEY"
```

See `deploy/hf-space/` in the [repository](https://github.com/FHIR4DS/fhir4ds)
for the exact container this demo runs.
